# ADR (architecture decision record)

A numbered page in `docs/adr/` that records one decision or one batch of work: its options, the limits set before the work and the measured results. Cited as 'ADR 0089' ([[doc-glossary]]).

## How rcfd uses it

- File names carry exactly one kind word: registration, amendment, diagnosis, proposal, plan, record, review, audit, job or wave; ADRs are append-only — results, answers and corrections are dated addenda ([[doc-process-agent-rules]], rule 18).
- Results go in 'Addendum 1: results'; open questions under 'Open questions for the maintainer'; the lead writes 'Answers of the maintainer (<date>)' ([[doc-process-agent-rules]], rule 8).
- `docs/adr/index.md` is a generated catalog (one row per ADR, grouped by roadmap category, with item and item status), regenerated by the lead via `scripts/process_report.py --write` ([[doc-process-agent-rules]]).
- About 794 ADR files at `origin/main` 2e94e5ef; ingest is planned per thread in P3 ([[ingest-plan]]).
- ADR numbers are given by the [[lead]] only, the next free number on main ([[doc-process-lead-process]]).
- Writers: the agent it was issued to writes an ADR "above its answers" on its branch; the lead writes the "Answers of the maintainer" section on main ([[doc-process-lead-process]], [[maintainer-questions]]).
- A citation from memory is closed by a "Sources read" addendum, never by an edit ([[sources-read-addendum]]); "An ADR finding is corrected by an addendum of that ADR, never by an edit" ([[doc-process-handover-2026-11-19]]).
- Scale on 2026-11-18: 736 files in docs/adr, 23.7 MB, about 3.9M words; before the index existed, ROADMAP.md named 645 of 736 ADRs ([[doc-process-documentation-review]], G1, G7). The index is written by [[process-report]] section b.
- Briefs under `docs/adr/briefs/` are not ADRs: no number, not read by the test index ([[doc-adr-briefs-readme]]).
