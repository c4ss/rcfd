# Example projects: README, manifest and project notes

**Origin:** [example-projects/README.md](../../example-projects/README.md), [example-projects/manifest.json](../../example-projects/manifest.json), the notes `wind-tunnel/notes/{README,cylinder,naca0012,step}.md`, `quick-start/notes/README.md`, `axial-fan/notes/README.md`, the `meshes/README.md` of quick-start and axial-fan, and the recipe header of `wind-tunnel/meshes/naca0012-ogrid.recipe.toml`, at origin/main 2e94e5ef. Also [example-projects-linux/README.md](../../example-projects-linux/README.md).
**Kind:** repo docs (user-facing project notes) plus the folder layout. Decisions: [ADR 0142](../../docs/adr/0142-wave48h-example-projects.md) (wind tunnel, quick start), [ADR 0150](../../docs/adr/0150-job48p-linux-example-stores.md) (Linux tree), [ADR 0176](../../docs/adr/0176-job49m-fan01-blade-passage-as-a-3d-example-project.md) (axial fan).

## Summary

"Finished project folders of the rcfd Studio (ADR 0142)": each holds case files, meshes, completed runs with stored fields, a design ledger and notes, "so the Studio shows a picture as soon as you open a project and select a run. No result in these folders is a validation: the meshes are coarse on purpose." Three projects: [[example-project-wind-tunnel]], [[example-project-quick-start]] (2D, one cell thick, drawn face-on) and [[example-project-axial-fan]] (3D, drawn in a view you can turn).

## Key points

- Open with Open project folder… (Ctrl+O) in the desktop Studio; start it as `docs/tutorials/desktop-assistant.md` says ([[doc-tutorial-desktop-assistant]]). The notes say "There is no installer yet: build `rcfd`, `rcfd-runner` and `rcfd-mcp` in release, then run `npm start` in `apps/studio-web/` with `RCFD_STUDIO_RCFD` set to the `rcfd` you built."
- To start runs of your own, copy the folder out of the repository first; new runs inside the checkout show up as untracked files. "Opening and looking write nothing into the folder."
- The real solver made the runs through the run service, with `scripts/make_example_projects.py`, which also rebuilds them, checks the committed folders against their case files (`--check`) and with `--rerun-check` rebuilds into a temporary copy and compares the reproducible files byte for byte.
- `manifest.json` (format `rcfd-example-projects-1`, ADR 0142, solver `rcfd 0.1.0`, platform windows x86_64, Python 3.9.13) lists the committed runs and size caps: total 40 000 000 bytes; wind-tunnel 35 000 000 (actual 28 096 175), quick-start 6 000 000 (4 250 540), axial-fan 6 000 000 (3 499 558). Tests `crates/rcfd-mcp/tests/example_projects_w48h.rs` and `scripts/test_make_example_projects.py` fail when a committed example goes stale.
- Each project follows the project folder contract ([[rcfd-project]]): `rcfd-project.json` (schema_version 1, name, created, solver_version_created), `cases/`, `meshes/`, `runs/r-<UTC>-<4 hex>/` (`run.json`, `case.snapshot`, `status.json`, `events.jsonl`, `log.txt`, `residuals.jsonl`, `metrics.json`, `check.json`, `fields/index.json` + `fields/store.rts`, `output/monitors.csv`, `monitors.json`, `report.html`), `designs/variants.ledger.jsonl` (ADR 0121 ledger, format `rcfd-ledger-1`, one line per run), `notes/`, `.rcfd/` (git-ignored). The `meshes/README.md` of quick-start and axial-fan exist only to keep the folder in git, "because the project folder contract (docs/ui-restart-plan.md, section 8) and `rcfd-project`'s validation expect it to exist".
- Common limits in every project's notes: fields stored in single precision (f32, ADR 0133), "each stored value is within |x| 2^-24 of the solver's value", solver in double precision; run records hold the absolute paths of the machine that made them (`case_source`, `case_dir` in `run.json`), "information only". Run tables in the notes are generated by `scripts/make_example_projects.py` between `<!-- generated: runs -->` markers.
- **Linux tree.** `example-projects-linux/` holds the same three projects with runs made on x86_64 Linux (ADR 0150): "mesh generators call the C library's libm, whose last bits differ between Windows and Linux (ADR 0137), so the mesh a run stored equals the mesh the same case builds only on the platform that made the run." Case files, mesh recipe, notes and `rcfd-project.json` are the same; the script copies them from `example-projects/` and builds in Docker (`scripts/docker/ubuntu-24.04-rust.Dockerfile`, Ubuntu 24.04, glibc 2.39, Rust 1.99.0); options `--docker`, `--docker --rerun-check`, `--docker --add-missing`. Its manifest records platform linux x86_64, Python 3.12.3, image `rcfd-linux:ubuntu24.04-rust1.99.0`. Caps apply to each tree on its own. Not ingested separately.

## Contradictions with the wiki

> [!warning] Contradiction
> Installers: the three project notes say "There is no installer yet" (consistent with [[doc-glossary]] and [[doc-readme]] on [[studio]]), while [[doc-studio-guardrails]] records "installers built in CI, signing waits for the maintainer's certificate". Within the repo docs; the notes may predate the CI installers.

> [!warning] Contradiction
> Mesh path in the case editor: `wind-tunnel/notes/README.md` (Limits) says the desktop Studio's case editor "opens a case file through the solver service, which resolves relative paths against the case's folder", while `wind-tunnel/notes/naca0012.md` (last bullet) says "The Case editor of the Studio cannot find the mesh of these two cases (its relative paths resolve against the Studio's working folder); runs are not affected. See `notes/README.md`, Limits." Within the repo docs (same project's notes).
